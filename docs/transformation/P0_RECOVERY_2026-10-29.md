# Password recovery boundary — 2026-10-29

The public password reset request returns only its generic `detail`, in every environment. `X-Debug-Recovery`, `debug_recovery`, host names and proxy headers cannot enable token disclosure or bypass rate limits. Tests must inspect locmem mail or synthetic token fixtures. No operational test-only route exists.

`REMOTE_ADDR` is parsed as an IP and used for audit/throttling only. There is no configured trusted-proxy chain; `X-Forwarded-For` is ignored here. Behind a proxy the IP limit aggregates at the peer (availability tradeoff); email rate limiting still applies. A future proxy-aware rate limiter must authenticate the proxy chain separately and must never grant recovery privileges.

Normal email recovery still issues a reset credential to the email channel. It does not issue session tokens, authorize a product, or bypass central SSO. Delivery failures invalidate the credential and log no exception text or email address. Central passwords and MFA remain AdminApps authority.
